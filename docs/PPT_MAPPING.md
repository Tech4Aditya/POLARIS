# Product ↔ Demonstration Traceability

Every major capability presented in the POLARIS presentation should map to
a corresponding product screen, API endpoint, workflow, or architecture
artifact.

| Presentation Area | POLARIS Implementation |
|---|---|
| Problem | Polar Archive / Discovery |
| Solution | POLARIS Overview Dashboard |
| Architecture | Docker Compose + service architecture |
| Knowledge Engine | Search + source-grounded retrieval |
| Multimedia | Multimedia Library |
| Dissemination | Content Studio |
| Governance | Editorial Review workflow |
| Education | Smart Education workflow |
| Deployment | Docker Compose |
| Impact | Product metrics + benchmark results |

## Traceability Rule

Every important claim made in the PPT should have supporting evidence in
the project:

- A working UI screen
- An API endpoint
- A persisted data model
- A documented workflow
- An architecture artifact
- Or a reproducible evaluation result

The PPT should communicate capabilities that can be demonstrated directly
from the POLARIS application.

This keeps the presentation aligned with the actual implementation and
prevents unsupported feature claims.
